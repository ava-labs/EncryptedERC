## Problem

Running `npm run compile` on Windows fails with:

```
Error: Cannot find module '..helpers'
```

`@solarity/zktype` uses `path.relative()` to build import paths in generated `.ts` files.
On Windows, that produces backslashes (`from "..\helpers"`), which Node cannot resolve as a module path.

The existing `postinstall` script also used `cmd &` instead of sequential `&&`, which breaks the compile chain on Windows.

## Affected files

- `generated-types/zkit/core/*.ts` (and `index.ts`) — autogenerated on `zkit make`

## Fix

- Add `scripts/fix-win-paths.js` — normalizes `\` → `/` in import/require paths after `zkit make`
- Add `scripts/run-compile.cjs` — cross-platform sequential compile pipeline
- Add `scripts/zkit-require-alias.cjs` + `scripts/run-zkit-verifiers.cjs` — fallback during verifier generation
- Update `package.json`: `compile`, `postinstall`, `zkit:*` scripts

## Testing

- [x] `npm run compile` on Windows 11 — 5 circuits compiled, 5 verifiers generated
- [ ] `npm run compile` on macOS/Linux (expected no-op path fix, 0 files changed)
- [x] `generated-types/zkit/core/BurnCircuit.ts` imports `from "../helpers"` after fix
